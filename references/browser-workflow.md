# 浏览器工作流

## 1. 建立任务空间并核对账号

先读 [账号绑定与发送状态](account-state.md)。每个账号使用已确认的独立 Ego Profile 和本轮专用任务空间。Profile 的选择和任务空间控制遵守 `ego-browser` Skill。

打开 BOSS 职位页并核对：

- 页面已登录且显示预期账号的脱敏身份。
- 当前选中的 AI 产品岗位求职期望存在，并从页面读取意向城市。
- 页面没有验证码、登录失效、账号异常或保护页。
- 保护工具 `status` 返回的筛选配置属于当前账号。

把实际账号身份、Profile ID、任务空间 ID 和城市写入本轮 `observed`。首次配置后使用 `start` 取得 `runId`；续投必须使用原 `runId`。占用冲突时停止，不创建别名或新状态目录绕过。

## 2. 建立候选池

只使用该账号已批准的搜索词与筛选规则。先从列表页读取可见候选中的标题、薪资、经验、城市、公司、行业标签、招聘者活跃状态和规范化岗位 URL，并立即按 URL 去重。列表位置不是稳定 ID。

列表信息足以判定不合格时直接跳过。只有 AI 相关性、行业、工作地点或招聘者活跃度仍不明确时，才进入详情核验。

若用户批准启用内置外包排除清单，再按公司名称和别名匹配；未启用时不使用该清单。普通公司不做公司级去重。

同一账号的浏览和发送保持串行，不并发打开多个详情或并发请求职位数据。分页或搜索结果没有新 URL 时切换下一个已批准搜索词；全部耗尽后如实结束，不重复刷新凑数。

## 3. 详情筛选

仅处理列表初筛后保留的候选。按已批准配置逐项核验：

- 职位标题和职责是否属于 AI 产品方向。
- 结构化城市、标题和 JD 中的实际工作地点是否一致。
- 薪资上下限及面议规则是否满足配置。
- 结构化经验要求与 JD 是否冲突；冲突时采用更严格结果。
- 行业和核心业务场景是否命中用户批准的排除项。
- 招聘者活跃状态是否在允许范围内。

任何一项缺失、无法解析或冲突时，按用户配置决定跳过；配置没有定义处理方式时不发送。

## 4. 发送前检查

每个候选必须取得实际招聘者 ID 和规范化岗位 URL。先核对本地账本，再等待会话历史完整加载，检查是否已有本账号发送过求职自我介绍。旧版或改写版话术同样算已联系。

发送前重新观察账号、Profile、任务空间、城市、岗位和招聘者。全部筛选通过且历史已检查后，调用 `prepare`。未返回 `ok: true` 不点击可能建立会话或发送消息的入口。一次许可只能用于对应岗位和招聘者的一次立即尝试。

## 5. 详情页弹窗

1. 取得许可后点击一次“立即沟通”，观察它是否已经产生消息。
2. 若出现平台默认招呼或其他非目标消息，保存 `unexpected_sent`；结果不明保存 `unknown`，两者都停止。
3. 若明确只打开尚未发送的编辑框，填入保护工具返回的完整话术。
4. 等待输入内容、收件人和发送按钮全部核对成功，再点击发送一次。
5. 只有弹窗同时出现本次完整话术和“已发送”时，才能保存 `confirmed`。

常见选择器可能包括 `a.btn-startchat`、`.startchat-dialog textarea.input-area` 和 `.startchat-dialog .send-message`，但必须先观察当前页面含义，不可盲用。

## 6. 沟通页输入框

已有会话可以进入沟通页只读核验。前一次动作可能已发送时，只能核验原 `attemptId`。

确认此前动作没有提交消息且历史完整加载后，才允许在当前许可内完成首次发送：

1. 核对当前会话和招聘者。
2. 已有本账号自我介绍时跳过。
3. 将完整话术写入 `.chat-input`，等待内容、收件人和按钮状态全部通过检查。
4. 点击 `button.btn-send` 一次，不依赖 Enter 键。
5. 本账号消息气泡同时包含完整话术及“送达”或“已读”后，保存 `confirmed`。

选择器变化、脚本异常、页面超时、用户接管或回执不明时保存真实阶段并停止。详情页和沟通页不能各发一次。

## 7. 记录与停止

筛选统计保存到本机状态目录，至少包含 `accountKey`、`runId`、`examined`、`urls`、`skips` 和 `notes`。稳定跳过原因可使用 `title`、`city`、`salary`、`experience`、`industry`、`activity`、`knownOutsourcingAvoid`、`contacted`、`sameRecruiter`、`chatMissing`、`sendUnverified` 和 `risk`。

验证码、账号异常、操作频繁、登录失效、当日沟通上限、环境异常或用户接管时立即停止。普通页面安全提示不能单凭文字标题判断为异常，需要结合实际页面状态。

恢复时先只读核验账号和待核验消息，再按账号状态文档执行 `resume`。正常完成时先 `finish`，再按 Ego 规则结束任务空间。
