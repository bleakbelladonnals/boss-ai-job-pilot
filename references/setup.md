# 首次配置

本 Skill 不提供可直接发送的个人默认值。示例、页面历史和其他账号的设置都不能形成当前账号的授权。

## 何时需要配置

先用保护工具执行只读 `status`：

- 当前账号尚未配置时，发送前必须完成首次配置。
- 用户改变话术或任一筛选条件时，只在没有未完成批次的情况下更新配置。
- 仅做登录、页面和输入路径检查时，可以暂不配置发送话术，但不能点击任何可能建立会话或发送消息的入口。

## 发送前必须确认的内容

从用户当前指令和页面观察中整理以下内容，并集中确认缺失项：

- 当前 BOSS 账号对应的脱敏身份，以及本轮使用的 Ego Profile。
- 当前 AI 产品岗位求职期望中的城市；城市必须从页面读取。
- 接受的职位方向和用于召回的搜索词。
- 薪资区间规则，以及是否接受面议或无法解析的薪资。
- 可接受的经验要求。
- 可接受的招聘者活跃状态。
- 排除行业或业务场景。
- 是否启用内置外包排除清单；未明确同意时不启用。
- 需要原样发送的完整话术及其中全部链接。
- 当前批次的目标发送数量。

不得自行补全任何会影响候选范围或对外消息的值。用户已经明确提供的内容直接采用，不重复询问。

## 保存配置

使用保护工具的 `configure` 写入：

- `accountKey`：稳定、非个人敏感的本地账号标识。
- `profileId`：实际 Ego Profile ID。
- `identity`：页面可重复核对的脱敏身份标识，不保存完整手机号、Cookie、Token、密码或验证码。
- `greeting`：用户批准的完整话术。
- `filters`：完整筛选快照，至少包含 `city`，并记录职位方向、搜索词、薪资、经验、活跃度、行业排除和外包清单开关。
- `approved: true` 与 `approvalEvidence`：只能对应用户对该账号及完整配置的明确批准。

配置只保存在接收者本机的状态目录，不写回 Skill 文件。不同求职者分别配置，不共享身份、话术、筛选条件和发送历史。

## 建议的首次验收

首次使用先执行只读流程：核对账号、城市、搜索结果、详情筛选和输入框路径，不发送。用户确认筛选效果及完整话术后，再新建有明确目标数量的发送批次。
